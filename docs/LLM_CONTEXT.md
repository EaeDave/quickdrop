# LLM Context

## Current business rule map

- Regra: A interface desktop (Tauri), a landing page web (`GET /`) e o cliente Windows via system tray aceitam 1 ou vários arquivos por ação via drag-and-drop, seletor ou `Ctrl+V`. A landing page também exibe comandos copiáveis de instalação em abas Windows (`irm https://quickdrop.eaedave.xyz/install.ps1 | iex`) e Linux (`curl -fsSL https://quickdrop.eaedave.xyz/install.sh | bash`). Com múltiplos arquivos, o desktop cria um ZIP temporário via Rust para caminhos locais e o cliente web/clipboard cria um ZIP via `fflate` em JS. Ambos enviam o pacote final como 1 upload para `POST /api/upload`, gerando 1 link público. Fonte: UI `src/desktop/App.tsx`; `src/desktop/tauri.ts`; comandos Tauri `src-tauri/src/lib.rs`; Backend `src/server/upload-service.ts`.
- Regra: `Ctrl+V` com imagem/arquivo do clipboard envia o arquivo colado; `Ctrl+V` com texto cria `quickdrop-paste.txt` (`text/plain`) antes do upload. No desktop Wayland, o atalho chama `wl-paste` nativo porque o WebView pode não emitir `paste` com imagem. No Windows, o app não intercepta o atalho nativamente e deixa o WebView2 entregar o `paste` padrão. Fonte: handler de teclado/paste em `src/desktop/App.tsx` e comando `uses_native_clipboard_paste` em `src-tauri/src/lib.rs`.
- Regra: upload público sem autenticação, com rate limit padrão de 5 uploads/hora/IP (`UPLOAD_RATE_LIMIT_MAX`) e kill switch `UPLOADS_ENABLED=false` para bloquear novos uploads sem derrubar downloads/instaladores. Fonte: Endpoint interno `POST /api/upload` registrado em `src/server/index.ts`, `src/server/config.ts`, `src/server/index.test.ts`.
- Regra: limite padrão 100 MB e rejeição de arquivo vazio/multipart inválido. Fonte: `src/server/config.ts`, `src/server/upload-service.ts`, testes `src/server/config.test.ts`.
- Regra: quota global R2 fail-closed por PostgreSQL, default `R2_STORAGE_HARD_LIMIT_GB=8`: antes do upload o servidor reserva bytes em `storage_reservations` e só aceita se `active_bytes + reserved_bytes + novo_arquivo` couber em `storage_quota`; se não couber, responde `507 storage_quota_exceeded`. Fonte: `src/server/storage-quota.ts`, `src/server/upload-service.ts`, `migrations/003_create_storage_quota.sql`.
- Regra: URL pública `${PUBLIC_BASE_URL}/f/:shortId` redireciona para signed URL do R2 e incrementa `download_count`. Fonte: Endpoint interno `GET /f/:shortId` em `src/server/download-service.ts`.
- Regra: expiração padrão de 6h; o job roda a cada 5 minutos, libera reservas vencidas, remove expirados do R2 e marca `deleted_at`, descontando bytes ativos da quota. Fonte: `src/server/expiration.ts`, Job interno `cleanupExpiredUploads` em `src/server/cleanup.ts`, CLI `src/server/cleanup-cli.ts`, `src/server/uploads-repository.ts`.
- Regra: desktop copia o link e notifica sucesso por integração nativa da plataforma. Linux/Wayland usa `wl-copy` e `notify-send`; Windows usa `tauri-plugin-clipboard-manager` e `tauri-plugin-notification`. Em múltiplos arquivos, o sucesso mostra um único link para o ZIP; se algum arquivo selecionado for inválido/vazio, o pacote não é enviado. Fonte: comandos desktop `copy_link`, `notify_success`, `upload_files` em `src-tauri/src/lib.rs` e UI `src/desktop/App.tsx`.
- Regra: no Windows, QuickDrop roda residente na system tray. Clique esquerdo ou menu `Abrir QuickDrop` abre/foca a janela; botão fechar/Esc ocultam a janela; menu `Sair` encerra o processo; o primeiro start ativa autostart automaticamente com `--tray-start` e grava marcador local para não reativar sozinho se o usuário desativar depois via menu `Iniciar com Windows`. Fonte: `src-tauri/src/lib.rs`, `src-tauri/tauri.windows.conf.json` e `src/desktop/App.tsx`.
- Regra: a instalação Windows por PowerShell (`GET /install.ps1`) baixa o instalador por `GET /windows/latest.exe`; esse endpoint usa `QUICKDROP_GITHUB_TOKEN`/`GITHUB_TOKEN` somente no backend para buscar o asset privado `QuickDrop_*_x64-setup.exe` da última release GitHub, sem expor token ao script público. `GET /` mostra o mesmo comando para cópia rápida. Depois do NSIS silencioso, o script abre o `QuickDrop.exe` instalado sem `--tray-start`, deixando a janela visível no canto direito e liberando o terminal sem esperar o processo residente da tray encerrar. Fonte: `src/desktop/App.tsx`, `scripts/install-windows.ps1`, `src/server/index.ts`, `src/server/windows-installer-service.ts`, `src/server/index.test.ts`.
- Regra: a instalação Linux por Bash (`GET /install.sh`, `curl -fsSL https://quickdrop.eaedave.xyz/install.sh | bash`) detecta Linux x86_64 e seleciona automaticamente OmarchyBar ou Waybar (`QUICKDROP_BAR=auto|omarchy|waybar|both|none`). Instala `~/.local/bin/quickdrop`, o launcher compartilhado `quickdrop-launcher`, o alias legado `quickdrop-waybar` e persiste o backend em `~/.config/quickdrop/config.env`. OmarchyBar recebe o plugin oficial `bar-widget` `quickdrop.bar` em `~/.config/omarchy/plugins/`; Waybar mantém o módulo idempotente `custom/quickdrop` com backup. Fonte: `scripts/install-linux.sh`, `scripts/install-bar-integration.sh`, `scripts/install-waybar-module.py`, `scripts/omarchy-quickdrop/`, `src/server/index.ts`, `src/server/linux-installer-service.ts`, `src/server/index.test.ts`, testes em `scripts/`.
- Regra: QuickDrop também oferece um relay de texto em tempo real para colar/copiar texto entre máquinas sem clipboard compartilhado. A web cria sala por `POST /api/text`, compartilha um código curto de 6 caracteres e sincroniza um textarea grande via `WS /api/text/:code/ws`; o snapshot inicial vem de `GET /api/text/:code`. O modelo é last-writer-wins com `version` monotônica, aviso não destrutivo quando chega atualização remota durante edição local pendente, limite padrão de 256 KB por sala e expiração após 12 horas sem clientes. O estado da sala fica persistido em PostgreSQL e sobrevive a restart/deploy; o processo só mantém o hub de conexões WebSocket em memória. A interface mostra presença em tempo real (`1 conectado`, `2 conectados`), mostra quando outros peers estão digitando, desenha o mouse remoto de cada peer dentro da área do editor e permite exportar o texto atual como arquivo `.txt` reutilizando o upload público do QuickDrop. Quando protegida por PIN, o backend valida `POST /api/text/:code/access` e libera leitura/WS por cookie HttpOnly por sala; o segredo não vai na URL nem no query string do WebSocket. Typing, pointer e peer cleanup são efêmeros; só o texto/version seguem persistidos. A entrada pode acontecer por host `texto.*`, por `?c=CÓDIGO` na raiz ou por `GET /t`/`GET /t/:code`, que redirecionam para a SPA com `?c=`. Fonte: endpoints internos `/api/text`, `/api/text/:code`, `POST /api/text/:code/access`, `WS /api/text/:code/ws`, `/api/upload`, redirects `/t` e `/t/:code`; `src/server/text-session-service.ts`; `src/server/text-room-access.ts`; `src/desktop/TextSession.tsx`.

## Technical map for future LLMs

 - Backend entrypoint: `src/server/index.ts` (Fastify, multipart, rate-limit, health, upload, download, cleanup startup; `GET /install.ps1` e `GET /install.sh` servem os instaladores PowerShell/Bash; `GET /windows/latest.exe` e `GET /linux/latest` fazem proxy server-side dos assets privados no GitHub; endpoints `/linux/quickdrop-launcher`, `/linux/install-bar-integration`, `/linux/install-waybar-module.py` e `/linux/omarchy/*` servem os adapters, enquanto `/linux/quickdrop-waybar` permanece compatível; serve a build do frontend via `@fastify/static`). O helper `src/server/github-release.ts` centraliza a resolução da última release + download autenticado.
- Backend CORS: `src/server/index.ts` registra `@fastify/cors` com `origin: true`, métodos `GET/POST/OPTIONS` e header `x-quickdrop-file-size`; isso permite que o WebView Tauri poste arquivos em memória ao backend remoto sem cair em erro de preflight. Regressão em `src/server/index.test.ts`.
- Persistence: PostgreSQL via Drizzle ORM on `Bun.SQL`; Drizzle Kit config in `drizzle.config.ts`; typed schema in `src/server/schema.ts`; DB helper in `src/server/db.ts`; migration SQL in `migrations/001_create_uploads.sql`, `migrations/002_create_text_rooms.sql`, and `migrations/003_create_storage_quota.sql`.
- Storage: Cloudflare R2 via AWS SDK v3 in `src/server/r2.ts`; object keys from `src/server/ids.ts` as `uploads/YYYY/MM/{uuid}-{sanitizedFilename}`. Cost guard tables are `storage_quota` and `storage_reservations`.
- Upload workflow: `src/server/upload-service.ts` accepts 1 multipart file per request, spools it to a temporary file with byte counting/limit enforcement, reserves global storage quota in PostgreSQL, inserts the upload while consuming the reservation, then uploads the temp file stream to R2. If R2 upload fails after the DB row exists, the service deletes the object when possible and marks the row deleted to release active quota; short ID retry lives in `src/server/storage-quota.ts`.
- Download workflow: `src/server/download-service.ts` rejects missing/deleted, deletes+marks expired (which releases active quota), otherwise signs R2 GET and redirects 302.
- Desktop Rust commands: `src-tauri/src/lib.rs` implements `upload_file`, `upload_files`, `read_clipboard_upload_inputs`, `copy_link`, `notify_success`, `dismiss_window`, `uses_native_clipboard_paste`; `upload_files` validates selected paths, creates a temporary `.zip` with unique entry names when there is more than 1 file, uploads that ZIP through the existing single-file backend endpoint, then removes generated temp files. `read_clipboard_upload_inputs` uses `wl-paste --list-types`/`--type` on Linux/Wayland to materialize clipboard image/text as a temporary local file for upload. Config reads `QUICKDROP_API_BASE_URL`; default is `https://quickdrop.eaedave.xyz` on Windows and `http://127.0.0.1:3000` on non-Windows unless the launcher/env overrides it.
- Desktop UI / Web Frontend: `src/desktop/App.tsx` funciona em ambos os ambientes (detectado via `isTauri`). No desktop usa drag-drop events do Tauri, seletor nativo e `Ctrl+V` via `wl-paste` somente quando `uses_native_clipboard_paste` retorna true; na web renderiza uma landing page com hero, card de instalação com abas Windows/Linux (comando + link `Ver script` para `/install.ps1` ou `/install.sh` conforme a aba selecionada via `INSTALL_PLATFORMS`), upload HTML5 por drag-and-drop/input e `Ctrl+V` via Clipboard API/eventos padrão. Mostra progresso real do upload e fase `Criando ZIP...` ao compactar múltiplos arquivos. A barra superior customizada chama `getCurrentWindow().startDragging()` para mover a janela frameless no Tauri.
- Text relay web-only: `src/desktop/main.tsx` desvia para `src/desktop/TextSession.tsx` quando `src/desktop/web-route.ts` detecta host `texto.*`, rota `/t`/`/t/:code` ou `?c=CÓDIGO`; o restante continua em `App.tsx`. `src/desktop/text-client.ts` fala com `POST /api/text`, `POST /api/text/:code/access`, `GET /api/text/:code` e `WS /api/text/:code/ws`, implementa reconnect com backoff, parseia `presence`/`typing`/`pointer`/`peer_left` e trata erros estruturados de acesso (`pin_required`, `pin_invalid`, `invalid_token`). `TextSession.tsx` agora usa uma janela curta de envio (~75 ms) com flush rápido em paste/blur, envia sinais efêmeros de `typing` e `pointer`, mostra labels coloridos por `clientId`, limpa peers remotos por timeout ou `peer_left`, mantém o banner de conflito remoto, exporta `quickdrop-room-<CODE>.txt` por `uploadFiles()` e preserva o fluxo de PIN opcional. No backend, `src/server/text-session-service.ts` relaya `typing`/`pointer` sem persistir nada, e `src/server/text-session-service.test.ts` cobre esses eventos além do fluxo persistido/protegido.
- Commands: `bun run server:dev`, `bun run server:start`, `bun run db:generate`, `bun run db:check`, `bun run db:migrate`, `bun run cleanup:run`, `bun run desktop:dev`, `bun run desktop:build:web`, `bun run desktop:build`, `bun run desktop:build:windows`, `bun run desktop:package:linux`, `bun run desktop:install`, `bun run desktop:install:local`, `bun run bar:install`, `bun run omarchy-bar:install`, `bun run waybar:install`, `bun run local:server:up`, `bun run local:server:stop`, `bun run quickdrop:install`, `bun run quickdrop:install:local`, `bun run typecheck`, `bun test`.
- Status-bar install: `scripts/install-desktop.ts` delegates to the same `scripts/install-linux.sh` used publicly. `scripts/install-bar-integration.sh` owns detection and adapter orchestration; `scripts/install-waybar-module.py` is the single JSONC patcher; `scripts/omarchy-quickdrop/` is a validated Omarchy `bar-widget`. `scripts/quickdrop-launcher` owns Hyprland positioning and reads the shared backend config, while `scripts/quickdrop-waybar` is a compatibility symlink. The Tauri window remains `380x220` internally/~`432x272` in compositor coordinates and supports `QUICKDROP_WINDOW_WIDTH`/`QUICKDROP_WINDOW_HEIGHT`.
- Windows tray: `src-tauri/Cargo.toml` enables Tauri `tray-icon`/`image-png` and native plugins for clipboard, notification, and autostart. `src-tauri/src/lib.rs` builds the tray only on Windows, uses `icons/icon.png`, positions the default/opened window above the tray/work-area corner instead of at the cursor, hides instead of closes on `dismiss_window`, enables autostart once on first launch, persists `autostart-configured` under the app config dir, and autostarts with `--tray-start`. `scripts/install-windows.ps1` intentionally does not pass `--tray-start` after installation: it waits for NSIS only, then starts the installed `QuickDrop.exe` detached/visible so the PowerShell prompt returns immediately. `src-tauri/tauri.windows.conf.json` enables NSIS bundling and Windows icons.
- Linux installer: `scripts/install-linux.sh` validates Linux/x86_64, downloads the binary and small integration assets, persists the API URL, then delegates to `install-bar-integration.sh`. Auto detection first checks the active `omarchy.bar` plugin through `omarchy-shell shell listPlugins`, then a live Waybar process, then config presence; explicit override wins. Production adapter logic is not duplicated in TypeScript: local installation invokes the same Bash/Python files. The release artifact remains `quickdrop_<version>_x86_64-linux` from `scripts/package-linux-release.ts`.
- Deploy backend: `Dockerfile` compila o frontend e copia para a imagem final todos os assets públicos de instalação Linux/Windows, incluindo launcher, detector/adapters, patcher Waybar e plugin Omarchy. O entrypoint roda migrações e inicia Fastify na porta `3000`. O proxy dos binários privados continua exigindo `QUICKDROP_GITHUB_TOKEN`/`GITHUB_TOKEN` no runtime.
- Local Docker backend: `compose.yml` has an optional `server` service behind profile `local-server`, with Postgres healthcheck, `restart: unless-stopped`, port `127.0.0.1:3000`, and `DATABASE_URL` overridden to `db:5432`. `quickdrop:install:local` starts it and writes `http://127.0.0.1:3000` to the shared QuickDrop config before installing the detected bar adapter.

## Conflicts and unknowns

- End-to-end upload/download requires real Cloudflare R2 credentials and PostgreSQL running; repository defaults do not contain secrets.
- Desktop Wayland flow requires local `wl-copy`, `wl-paste`, `notify-send`, Tauri Linux system dependencies, and a graphical Wayland session. Windows tray/notification verification requires a Windows machine with WebView2; notification branding is only correct for installed apps.
- Deploy Dockerfile covers the backend HTTP service only. Daily desktop use should prefer the remote backend unless the user explicitly wants the optional local Docker backend; Windows defaults to `https://quickdrop.eaedave.xyz`, and Linux stores the same default in `~/.config/quickdrop/config.env`. The public binary routes require a server-side GitHub token at runtime. The Linux release remains a dynamically-linked x86_64 binary built on Arch/Omarchy (webkit2gtk-4.1/gtk3), targeting Arch/Hyprland-like systems.
